# 二染色 Solver–Challenger 实施计划

目标是运行完整的 API 交互循环，确定性验证每个动作，再根据同题多轨迹生成下一轮挑战。参数训练只导出交接数据。
此文档保留初版的实施范围，当前运行方式和奖励见 [项目说明](../README.md)。

## 结构与约定

- `bicolor/graph.py` 负责图、翻转、精确计分、最短修复步数与题目生成。
- `bicolor/clients.py` 负责 Chat Completions 兼容接口，以及明确标注的离线模型替身。
- `bicolor/loop.py` 负责内循环、同题多采样、题型均分、Challenger 诊断及下一轮生成。
- `bicolor/train.py` 只导出状态—动作—奖励数据，并明确标记参数训练尚未接入。
- `bicolor/__main__.py` 提供配置、调用预算、运行记录和错误状态。
- `tests/` 验证手算、难度证明、二轮反馈、HTTP 协议、训练导出和逐行注释。
- `docs/architecture.svg` 和 README 展示完整循环及预留训练分支。

初版使用小型连通二分图。bridge 为两个中心相连、各带 size 个叶子的树；chain 为相同点数的链。两类图边数、初始分和最少翻转次数相同。size 限定为 2–4，支持穷举所有状态核验。
每步奖励等于合格边比例之差，成功得分为 1。达到预算仍未成功会记录 budget_exhausted。
Solver 只获得图、当前状态、历史动作和实际分数，不获得最优路径或最短距离。
Challenger 读完整轨迹与统计，输出假设、引用轨迹 ID、预测行为、目标题型和规模。程序生成两道目标题和一道对照题。
初轮来自固定种子。后续轮次使用已验证的 Challenger 输出、来源轮次和新的种子。图名随机置换，同种子可复现。
API 与离线模式共用真实环境和调度。API 模型、地址、密钥由用户配置；离线结果明确标注 offline_simulation。
Python 标准库实现，无 GPU 依赖。所有新增非空 Python 代码行附中文注释。
