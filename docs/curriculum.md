# 双角色课程、调度与反馈

默认运行两轮同步交互，每批两道目标题、一道对照题，历史重测默认关闭。下面的离线配置会运行四轮，在第 2、3 轮（轮号从 0 开始）各混入一道旧题。把 `async` 改成 `sync` 即可对照两种调度。旧配置名 `prefetch_one` 仍可使用，等价于 `async`。

```toml
[run]
mode = "offline"
seed = 42
rounds = 4
rollouts_per_task = 1
initial_size = 2
completion_bonus = 1.0
schedule_mode = "async"
historical_tasks_per_round = 1
historical_start_round = 2
```

保留 `[api]` 段，运行、回放和导出命令见 README。这个例子每题最多翻转 3 次，四轮共 14 题，另有 3 次 Challenger 提案。若改用 API，最多调用模型 45 次。离线模式的模型调用数为 0。

## 时间、身份和反馈

| 求解批 | 同步出题观察 | 一批预取的观察 | 提案 |
|---|---|---|---|
| Q0 | 种子 | 种子 | 无 |
| Q1 | H0 | H0，预热 | decision-0 |
| Q2 | H1 | 解 Q1 时消费 H0 | decision-1 |
| Q3 | H2 | 解 Q2 时消费 H1 | decision-2 |

Hk 指第 k 轮完整的轨迹、统计与已结算评价。两轮运行没有可重叠的后续批次；三轮可以检查首次重叠；四轮可以看到预取的 Challenger 消费首次模型提案的已结算反馈。每个提案记录 observation_round、planned_round、原始输入与输出。评价按任务绑定的 decision_id 关联；历史题保留 origin_task_id，自己的 decision_id 为空。

同步模式在同一个线程依次出题、解完整批、发布反馈。异步模式中，后台 Challenger 把整批题放入容量为 1 的队列，Solver 在前台按顺序取走。取走一批就释放一个备题位置，此时 Challenger 可以提前准备下一批。队列空时 Solver 等题。另一个反馈队列只传已经结算的批次，确保 Q2 的出题依据固定为 H0。两条路径最终调用同一个求解和计分函数。

反馈保留上一已观察批次的挑战分、诊断分、预注册预测、命中数、分组监控、历史重测结果及覆盖情况。评价是否影响下一动作取决于策略；固定权重模型读入反馈不会触发梯度更新。模型标识采用实际配置的名称；使用指向可变服务版本的别名时，不能据此确认远端权重版本。

## 两个评价量

- challenge_reward 为有效目标题中的预算失败比例；若本批任何目标题动作无效或没有目标题，则没有可用挑战分。对照和历史组不参与分母。
- diagnostic_quality 仅在预注册 undo_after_drop 且目标/对照均可评价时计算，取目标命中率减对照命中率。两个终局预测仍报告命中数，但不为其重复赋予诊断质量分。
- 保留单次提案的奖励与质量分量，不预设两项的最优训练权重。结构、模型、组别和有效分母随结果保留；同构题重复采样不能代替结构泛化实验。

## 历史题重测

从指定轮次起，每批最多抽 `historical_tasks_per_round` 道出题方已经观察到的历史目标题。候选不足时取全部。比如 Q2 开始重测，同步可抽 Q0、Q1 的原题，异步只可抽 Q0 的原题。候选按原始题号去重，批内无放回，以后仍可再次抽到同一题。

重测保留原图、节点编号、初始着色和预算。Solver 从头作答，按这次动作重新计分。原答案和旧动作不会进入提示。当前目标题和对照题的种子不随重测开关变化。重测耗尽预算不会奖励本轮 Challenger。这里可以观测已见题的表现；要衡量抗遗忘作用，还需实际更新权重并比较开启、关闭重测的训练结果。

## 证据文件

- decision-N.json：提案身份、可见反馈和预定批次。
- schedule-N.json：实际任务、明确组别、来源与图证书。
- episodes.jsonl、rounds.jsonl、summary.json：轨迹、评价、分组统计与重测变化。
- timing.jsonl：各批接收前的实际等待秒数，含同步出题等待，不纳入确定性奖励比较。预取速度收益需在相同预算、服务并发限制和题量下实测。
- partial-N.json：求解被中断时的分组监控。未完成的批次没有有效出题奖励。已发出的真实 API 请求可能仍会完成并产生费用。
