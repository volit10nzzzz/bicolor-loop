# 双角色反馈、调度与历史题重测：开发规格

v3 已实现并通过离线验证。本文保留设计与验收口径，运行示例见 [课程与反馈](curriculum.md)。模型难度基线留给选定模型后的实验。

## 1. 分项奖励

Solver 沿用分差与一次性完成加成，分开记录。Challenger 对自己提交的目标组获得 challenge_reward，即有效评价中的预算耗尽比例。沿用 v2 缺失语义，目标组为空或含无效动作则整次挑战评价未知，运行故障保留未完成状态。

质量先定义为“这组题能否有针对性地复现预先预测的行为”。对预注册的行为事件 undo_after_drop，记录目标组与匹配对照组的命中数、回合数，以及 diagnostic_quality = 目标命中率 − 对照命中率，范围 [-1,1]。任一组证据缺失、为空或含无效动作则该分量为 null。solved 和 budget_exhausted 仍可报告预测命中；作为终局预测时质量分量标为不适用，避免用失败率重复给分。合法性、可解性、预算充足是准入条件。训练出口保留 challenge_reward 标量与质量分量，本期不假设两者的最优权重。此指标衡量事件区分度；对照图结构不同，不能单凭该数值证明因果诊断或学习收益。

验收：目标四次全失败但无人撤销，对照两次也无人撤销，挑战分1、质量分0。目标四次中两次撤销，对照两次中一次撤销，质量分仍为0。种子题没有出题动作，任何出题奖励均不归给模型。

## 2. 反馈与强度监控

在提出决策时冻结已完成的观察快照。反馈明确关联 decision_id、被检验的预测、题型与规模、目标与对照样本量、命中数、部分奖励和覆盖情况。首次观察允许没有已结算提案。只有快照截止时间前已经产生的结果可见。

按 solver 模型/版本、题型、结构规模、最短步数、首步条件及样本来源（目标/对照/历史）报告成功、预算耗尽、无效动作数量；接口中断单列。报告成功率时同时给有效分母、计划样本量和实际完成数。闭环总体强度先用这些指标观测。将来衡量课程收益时使用固定独立评测集，并与固定 bridge 或随机课程在相同预算下比较。

验收：决策输入中的反馈可以从此前结果重建；当前决策尚未发生的评价不能出现在输入中。难度标签描述题结构，模型成功率单列。

## 3. 一批预取

建议保留 sync 默认，另设 prefetch_one。第0轮为种子，结束后用 H0 生成第1轮题。预取模式从第1轮开始，在 Solver 解 Q1 时并行使用已冻结的 H0 准备 Q2。一般地，同时执行 solve(Qk) 和 propose(H[k−1], for_round=k+1)。首次重用 H0 的两次决策必须有各自 ID。末轮停止新增提案。

每个批次显式携带 decision_id、observation_round、planned_round，实际求解后写 evaluation_round；另记出题与求解模型标识、等待时间及请求消耗。种子批的 decision_id 为空。v3 按题单归属核验，v2 历史运行仍使用同步调度。共享预算在并发前预留，API 调用日志带请求 ID；回放按观察与动作所属回合/步定位，不能依赖网络返回顺序。生产失败或求解失败时停止新任务，保留已发请求的真实记录与开销。

验收：三轮足以覆盖首次预取；用受控事件而非 sleep 验证两个角色确实重叠。Q2 的输入只含 H0 可见信息，奖励归属于生成 Q2 的动作；人为倒置返回顺序仍可回放，预算不超限。同题由求解时的 Solver 作答；记录实际行为策略版本供后续训练适配。

## 4. 历史题重测

historical_tasks_per_round 默认为0。启用后从截止快照内此前轮次已求解的原始目标题按 origin_task_id 去重，无放回抽 min(n, 候选数) 道。抽样使用独立可复现的随机流；同构重编号保留结构组标签。重测结果不重新进入候选池。推荐每道历史题沿用每题 rollout 次数，记录由此增加的实际请求。

重建原始边、编号、初始着色和步数预算，为本次作答分配新 episode_id。Solver 观察只含正常题面与本次历史。历史组的 Solver 照常获得步奖励与答案奖励。历史组与目标组可能同属 bridge，所以 evaluate_challenger / prediction_results 必须按显式组别和决策 ID 筛选，不能再仅凭 family 推断归属。报告重测前后成功与撤销变化。多条 rollout 比较按原题汇总并报告次数。历史题接触过训练时，重测指标解释为已见题表现。

验收：开关为0时无额外请求；只有一道候选却要求两道时只抽一道；同一道 bridge 历史题由成转败不能改变当前 Challenger 奖励分母；重测不向 Solver 泄露旧答案或旧轨迹。

## 交付顺序

1. 修复已复现的回放契约问题：保留原始响应及执行动作，回放比较模型实际收到的完整观察。用正常附加字段和被改写的输入分别做回归。为历史 v2 证据保留按其已记录字段验证的入口。
2. 先在同步路线引入决策 ID、显式分组、分项评价与反馈，再接历史重测。检查默认值下目标题、对照题及 Solver 奖励保持原语义。train.py 导出观察时不得带入本次动作的后验结果。
3. 最后接并发预取，验证同步与异步奖励归属、乱序记录的回放和请求上限。README 与架构图只在实现通过后标记已支持。
